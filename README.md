# LEVEL 3.1

Личная RPG-система для целей, ежедневных действий и развития навыков.

## LEVEL 3.1 — системы приложения
- Персонаж: общий уровень, активность XP, прогресс и достижения.
- Квесты: ежедневные задачи, даты, приоритеты и привязка к долгосрочным целям.
- Долгосрочные цели: сроки, этапы и измеримый прогресс.
- Дерево навыков: независимая прокачка каждого навыка.
- Proof of Skill: числовой результат, единица измерения, тип и описание доказательства; история испытаний сохраняется; повторное испытание с тем же названием и единицей подтверждается только при улучшении результата.
- Привычки: ежедневные отметки, история выполнений и серии.
- Проекты: описание результата и статус.
- Финансы: журнал доходов и расходов, баланс.
- Пауза на день для болезни или объективных обстоятельств.
- Экспорт и импорт JSON-резервной копии.
- PWA-манифест и service worker для установки и офлайн-оболочки.
- Облачная синхронизация полного снимка через Supabase; конфликт локальной и облачной версий требует явного выбора.
- Вход по email и паролю. Первое подключение подтверждается одноразовой ссылкой, после чего пользователь задаёт пароль в браузере.

## Правила прогресса
- Общий XP отражает активность: впервые выполненный квест даёт +10 XP; ежедневная привычка — +5 XP один раз за день.
- Повторное переключение задачи или привычки не позволяет фармить XP.
- XP навыка начисляется отдельно за подтверждённый Proof of Skill и не смешивается с общим XP персонажа.
- Уровень навыка растёт независимо от других навыков.
- Повторный результат по той же метрике должен быть лучше предыдущего подтверждённого результата.
- Уже заработанный XP не отнимается за пропуск; серия дисциплины может сброситься.
- Подтверждение доказательства — ручное действие пользователя. Приложение не проверяет автоматически подлинность файлов или ссылок.

## Приватность
Локальная копия хранится в localStorage браузера. Если пользователь включает синхронизацию, полный снимок LEVEL (в том числе финансы, здоровье и питание) передаётся в Supabase в таблицу с включённым RLS и доступом только к строке текущего пользователя. Во frontend используется только publishable key; service_role key в приложении отсутствует. Не подключай аккаунт на чужом устройстве. Сам GitHub-репозиторий публичный: не добавляй сюда личные данные, пароли, токены или финансовые документы. Регулярно экспортируй резервную копию.
